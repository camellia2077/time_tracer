## [v0.2.5] - 2026-07-28

### 技术改进/重构 (Changed/Refactor)

本次改动围绕 `tracer_core` 的 canonical-key-first alias TOML 语义展开。核心目的是让 Core 成为 alias hierarchy 规则和测试的唯一语义来源，同时更新 log_generator 的 TOML 读取和测试数据配置，使生成器能够使用与 Core 测试一致的输入资产，支持 Core 独立验证 alias 解析与 canonical 映射，而不在 log_generator 中重复实现业务规则。

* 更新 alias TOML 加载契约，改为读取 canonical-key-first 结构：普通条目使用 `canonical_leaf = ["alias1", "alias2"]`，加载器展开 alias 数组并结合 parent、group hierarchy 构造完整 canonical path；同一 canonical 支持多个 alias。这样可以让 log_generator 正确消费 Core 定义的新 TOML 语义，并为同一 canonical 生成多个可用 alias。旧的 `alias = "canonical_leaf"` scalar 结构不再支持。
* 将 log_generator 的构建时配置来源从共享 `assets/tracer_core/config` 切换到面向测试/打包的 `assets/tracer_core/config_test`，与 Core 测试及配置快照使用同一套完整 alias 样例。这样可以让 Core 和 log_generator 使用一致的 test/data 输入，避免生成器误读分发用的空白 alias 配置，也方便通过测试资产验证 Core 的解析结果。
* 更新使用文档，明确新的 alias TOML 形状和不再支持的旧格式；版本号升级为 `0.2.5`。这样可以同步记录 Core 侧配置契约的变化，避免测试数据维护者继续按照旧 scalar 格式更新 TOML。
* log_generator 仅作为 canonical-key-first alias TOML 的只读消费者：它不负责编辑 alias hierarchy，不负责 TXT token replacement，也不负责 alias TOML、TXT 或数据库迁移。这样可以保持工具职责单一，将 alias 语义、编辑和迁移行为留在 Core 及其宿主迁移流程中，避免 log_generator 形成第二套规则实现。
