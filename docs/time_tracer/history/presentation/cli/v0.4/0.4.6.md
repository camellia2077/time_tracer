## [v0.4.6] - 2026-07-30

### 关联版本

* Core：`tracer_core v0.11.0`

本次改动的核心目的是让 Windows CLI 使用 Core 统一的配置与交换处理，并重新划分导出内容的边界。旧版导出会包含部分程序 Runtime 依赖的资源，例如图表 HEX 颜色定义和 Markdown 字段文本；这些资源在 Android 中属于 APK 内置的 `assets`，本身不可修改，因此再次导入也不会产生实际效果。新版 CLI 只交换用户真正需要备份和迁移的 `txt/**` 与 `config/user/**` TOML，使导入内容能够被解析并写入数据库。外部 bundle 验证时，CLI 再使用自身的 `config/program/**` 完成 Runtime 校验，但不把这些程序资源当作交换输入。Heatmap 则将程序内置 palette 与用户可调整阈值分开存放，同时保持报表渲染行为不变。

### 技术改进/重构 (Changed/Refactor)

* 重构 Windows CLI runtime 配置路径，统一使用 `config/program/**` 承载程序资源，使用 `config/user/**` 承载 `behavior.toml` 与 `activity_hierarchy/*.toml` 等用户配置。
* 重构 alias/activity hierarchy 命令示例、参数校验、诊断检查和运行时访问路径，全部迁移到 `config/user/activity_hierarchy/**`。
* 重构 `pipeline validate bundle`，改为验证外部 `user/` 配置与 TXT 数据，并在临时目录中补齐 CLI 自带的 `config/program/**`；验证过程仍不写入用户数据库。
* 重构 heatmap 配置加载，将程序调色板读取自 `config/program/charts/heatmap.toml`，将用户阈值读取自 `config/user/heatmap.toml`，并保持图表渲染参数合并后的 CLI 行为。
* 更新 CLI 配置发现、启动错误提示和 doctor 检查，使缺失配置时明确指向 `config/program/config.toml` 或对应的 `config/user/**` 路径。

### 修复 (Fixed)

* 修复 CLI 外部 bundle 校验仍要求旧 `config.toml` 与扁平 `activity_hierarchy/` 目录的问题，避免将程序展示资源误当作交换输入。
* 修复 heatmap 在程序默认调色板与用户可调阈值拆分后无法定位或解析配置的问题。

### 弃用/删除 (Deprecated/Removed)

* 删除 CLI 对旧扁平 `config/`、`config/activity_hierarchy/**` 和单文件 heatmap 配置路径的依赖。
