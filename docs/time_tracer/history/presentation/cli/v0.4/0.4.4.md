## [v0.4.4] - 2026-07-28

### 技术改进/重构 (Changed/Refactor)

本版本是对 `tracer_core` v0.10.7 alias hierarchy 能力的 Windows CLI presentation 适配，改动顺序上位于 Core 语义统一之后。Core 先接管 canonical-key-first TOML、hierarchy 编辑、校验和 replacement 计划，CLI 再把命令行参数和文件系统操作接到 Core runtime 上。改动目的，是让 CLI 与 Android 消费同一套 Core 结果，不再因各自解析 TOML 或推导 canonical 而产生行为差异。

* 新增 `AliasHierarchyClient`，将 `alias add`、`alias promote`、`alias add-group-alias`、`alias rename-group-alias`、`alias move`、`move-config` 和相关 rename 操作改为调用 Core 的 `apply_alias_hierarchy_operation`，由 Core 负责 TOML hierarchy 修改、校验、canonical 路径计算和 alias collision 检查。CLI 只负责把命令行输入转换为 Core operation，并展示 Core 返回的结果。
* `move` 和 `rename-group` 改为消费 Core 返回的 updated TOML、canonical replacements 和 alias-key replacements。因为一次 alias 操作可能同时影响 TOML、历史 TXT token 和数据库，CLI 仅负责读取文件、把 Core 返回的 TOML 纳入事务、调用 Core TXT replacement、候选数据库重建、失败回滚和命令行交互，不再在 Rust presentation 层推导 TOML 或迁移计划。
* `group alias` 改名现在被视为完整的 alias token 迁移：CLI 同时消费 Core 生成的 `alias_replacements`，对 TXT 中原 group alias 做精确替换，再进行候选数据库重建和切换，避免只修改 TOML 后旧 token 无法识别。
* `tree` 命令改为通过 `render_alias_hierarchy_text` 请求 Core 渲染，CLI 删除本地 alias TOML 解析、序列化、遍历、校验、canonical 推导和旧 rename binding。这样树展示也直接反映 Core 的 hierarchy snapshot/渲染结果，确保 Windows CLI 与 Android 使用同一套 alias hierarchy 语义。
* 将 CLI runtime 入口及动态加载从 `tracer_core_runtime_txt_json` 切换为 `tracer_core_runtime_config_json`，同步更新 capability、ffi、runtime loader、配置 bundle、测试 suite 和错误提示。
* 更新 CLI 运行时 alias TOML 快照和测试 fixture，适配 canonical key 位于左侧、alias 数组位于右侧的新格式；保留分发配置中的空白 alias 默认文件，不把测试 alias 集合当作用户分发配置。

### 弃用/删除 (Deprecated/Removed)

* 删除 Rust CLI 本地 alias TOML hierarchy 编辑器、解析/序列化逻辑、alias 唯一性校验、canonical 路径推导及旧的 rename action binding；所有 alias TOML 内容修改统一复用 Core runtime operation。

### 兼容性说明

* CLI 仍拥有命令参数、文件系统遍历、候选 TXT/数据库迁移和回滚编排，但不拥有 alias TOML 的业务语义。Core 返回的 updated TOML 和 replacement 是迁移流程的唯一依据；CLI 不得先单独保存 TOML 再修改 TXT。
* 空 replacement 只表示没有历史 TXT token 需要替换，配置变更仍须经过候选数据库验证和原子提交。
