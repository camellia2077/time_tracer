## [v0.6.2] - 2026-07-29

### 关联版本

* Core：`tracer_core v0.10.8`

### 技术改进/重构 (Changed/Refactor)

本次改动的目的是让 Android 的 activity 配置编辑与 `tracer_core v0.10.8` 保持一致，使用户能够在移动端调整 activity 的 `parent` 分组、修正错误分类并更新统计报告中的分组展示。Android 负责收集编辑意图和执行宿主侧迁移；Core 负责生成统一的 TOML 更新结果和 canonical replacement，避免 Android 与 Core 的分类规则产生分歧。

* 将 Android runtime 配置快照从 `aliases/` 迁移到 `activity_hierarchy/`，同步更新 `config.toml`、bundle、同步状态、资产校验和配置文件存储路径。
* Android activity hierarchy 操作改为复用 Core 生成的 TOML 更新结果和 canonical replacement，支持 activity canonical name 的变更，并将结果交给宿主迁移流程处理。
* 更新 Android runtime gateway、JNI bridge、配置目录发现和 activity hierarchy service，使 Android 使用与 Core/CLI 一致的 `activity_hierarchy/` TOML 语义。

### 弃用/删除 (Deprecated/Removed)

* 删除 Android 对旧 `aliases/` 配置目录和旧 alias hierarchy service 的依赖。

### 兼容性说明

* 本版本已复用 Core 的 activity hierarchy TOML 内容更新和 canonical replacement，但尚未复用 Core 的 activity hierarchy TOML 文件重命名及对应 `parent` 重命名能力。暂不接入这部分能力，是因为需要先明确区分根目录 `assets` 中的编译输入与用户修改后的配置文件：用户修改后的 `activity_hierarchy` 必须放入私有目录，才能安全支持文件名变更。
* Android 的测试/调试输入改由 ADB 传入 TXT 和 `activity_hierarchy` 配置；测试不再将 `test/data` 和 `activity_hierarchy` 一并打包进 APK 的 `assets`，以保持编译资产与用户可修改配置的边界清晰。
* Android 运行时配置必须使用 `activity_hierarchy/` 路径，旧 `aliases/` 快照不再受支持。
