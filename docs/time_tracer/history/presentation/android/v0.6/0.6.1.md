## [v0.6.1] - 2026-07-28

### 技术改进/重构 (Changed/Refactor)

本版本是对 `tracer_core` v0.10.7 alias hierarchy 能力的 Android presentation 适配，不是独立的一套 alias 编辑实现。Core 先统一了 canonical-key-first TOML、hierarchy 操作、校验和 replacement 计划，Android 再将 UI 和宿主迁移流程切换为消费这些 Core operation 结果。改动目的，是让 Android 与 Core 保持同一套 alias 语义，避免 Core 更新后 Android 继续按旧 TOML 或旧规则工作。

* 重构 Android alias TOML 编辑链路，新增 `AliasHierarchyGateway` 和 runtime service，统一调用 Core 的 alias hierarchy operation、snapshot、跨文件校验、初始文档创建和树渲染能力。这样 Android 可以直接消费 Core 对 canonical-key-first TOML 的解析结果，不再自行决定 TOML hierarchy、canonical 路径、alias 唯一性或 canonical/alias 改名规则。
* structured editor 的新增、删除、移动、提升、重命名、group alias/leaf alias 修改均改为提交 Core operation。由于 canonical 或 alias 改动可能同时影响 TOML、历史 TXT token 和数据库，Android 不直接保存 alias TOML，而是把 Core 返回的 updated TOML、`replacements[]` 和 `alias_replacements[]` 统一交给 `RuntimeAliasMoveMigrationService`；该服务负责 TXT replacement、候选数据库重建、失败回滚和成功后的原子提交。
* raw TOML editor、alias 导入校验和新 alias 文件创建改为复用 Core 的 validation/create/rewrite port。这样即使用户直接编辑 TOML，输入也仍由 Core 按统一契约重新校验和序列化。Android presentation 仅负责读取文件和收集用户输入；所有 alias TOML 落盘都必须通过迁移服务。新建文件使用 Core 生成的初始 TOML 和空 replacement plan 进入同一候选验证/提交流程。
* alias hierarchy 树展示改为消费 Core snapshot 或 `render_alias_hierarchy_text` 结果，删除 Android 本地 TOML parser、serializer、editor codec、hierarchy validator 和本地编辑 use case，避免 presentation 与 Windows CLI 保留第二套 alias 语义。
* 将 Android JNI/runtime 调用从 `nativeTxt` / `tracer_core_runtime_txt_json` 切换为 `nativeConfig` / `tracer_core_runtime_config_json`，同步更新 gateway、协议模型、能力字段、配置资产、迁移服务和相关测试。

### 弃用/删除 (Deprecated/Removed)

* 删除 Android 侧独立的 alias TOML 解析、序列化、编辑编解码、层级校验和 hierarchy 编辑 use case；alias TOML 的内容修改全部由 Core 决定并产出。

### 兼容性说明

* Android 仍负责宿主侧文件遍历、迁移事务和 TXT/数据库落盘编排，但不再直接保存 alias TOML，也不再从展示树反推 TOML 或迁移计划。Core 是 alias TOML hierarchy、校验、canonical 计算和 replacement 的唯一语义来源；Core 通过 TXT replacement action 产出修改后的 TXT，Android 负责将其纳入候选事务。
* 空 replacement 只表示没有历史 TXT token 需要替换，不表示可以绕过迁移服务；alias TOML 仍必须经过候选数据库验证和原子提交。
