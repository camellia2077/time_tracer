## [v0.12.10] - 2026-09-21

### 关联版本

* Android `v0.7.14`

### 新增功能 (Added)

* 为 tracer exchange 增加普通目录 carrier 的导入与内容导出能力；导出的普通目录与 ZIP 均使用根目录 `manifest.toml` 描述 `config/user/**` 和 `payload/**` 文件。

### 技术改进/重构 (Changed/Refactor)

* 放宽普通目录 carrier 的导入前置条件：缺少 `manifest.toml` 时根据实际的 `config/user/**` 和 `payload/**` 文件生成临时清单后继续走同一套路径、内容和完整性校验；ZIP carrier 仍要求标准 manifest。
* 统一纯文本目录导出与 ZIP 导出的 exchange 包格式，使两种 carrier 共享同一份 `manifest.toml`、目录层级和导入校验逻辑，避免因目录结构不同而维护两套导入路径。
* 将普通目录包和 ZIP 包统一接入 Core exchange 校验、解码和导入流程，严格校验 manifest 声明的文件集合、路径安全性和内容完整性。
* 将配置安装、备份和回滚扩展为完整处理 `config/user/**`，避免导出的额外配置文件在导入时被忽略。
* 为 SQLite persistence repository 增加 `EnsureDatabaseReady()`，允许 Android runtime 在配置校验成功后创建完整的空数据库 schema，而不插入业务记录，从而区分“数据库存在但没有数据”和“数据库不存在”。
* 为 Insights 查询和通用 data query 区分数据库不存在与数据库打开失败，分别返回“database is not available”和“database could not be opened”语义的错误信息，便于 presentation 层显示正确的无数据状态或真正的错误。

### 修复 (Fixed)

* 修复 exchange 导入未实际应用导入包中 `behavior.toml` 的问题，改为使用已解码的包配置执行安装。
