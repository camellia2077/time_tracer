## [v0.10.7] - 2026-07-28

### 新增功能 (Added)

* 新增统一的 alias TOML hierarchy 模型 `ActivityHierarchyDocument`，将 `parent`、group、leaf、group alias 和 leaf alias 解析为 Core 内部结构，并统一提供 canonical 路径计算、层级快照和文本树渲染能力。引入该模型的直接意图是简化 canonical 别名配置：旧格式需要为同一个 canonical 重复声明多条 alias，配置内容冗余，presentation 也难以围绕一个 canonical 统一执行 alias 新增和删除。新的 alias TOML 规范由 canonical key 位于左侧、alias 数组位于右侧，例如 `canonical_leaf = ["alias1", "alias2"]`；即使一对一配置，也能直观看出左侧是 canonical、右侧是 alias。一个 canonical 可对应单个或多个 alias，group 使用 `group_aliases = [...]`，从而让 Core 和 presentation 都以 canonical 为统一编辑单位；旧的 `alias = "canonical_leaf"` 标量写法不再支持。
* 新增 Core alias hierarchy 编辑能力 `ApplyAliasHierarchyOperation`，解决 presentation 只修改 alias TOML 而未同步迁移 TXT token 的问题：读取新的 alias TOML 后，旧 alias 已不再属于当前有效的 alias 集合，但历史 TXT 中对应的活动记录仍保留旧 alias 内容，导致这些活动 token 无法被识别并出现解析报错；本轮 group alias 改名曾出现的旧 token 报错正属于这一类状态不一致。该能力覆盖新增/删除 group、leaf，设置 leaf/group aliases，leaf 提升与移动，parent/group/leaf canonical 重命名，以及 group alias、leaf alias 改名和追加。操作返回 updated TOML、`replacements[]`、`alias_replacements[]` 和 hierarchy snapshot；Core 决定 TOML 语义及 token replacement，宿主负责通过 Core TXT action 和事务服务同步修改 TXT、重建候选数据库并完成原子迁移。
* 新增 alias hierarchy 的结构化能力，允许 Core 接收 alias TOML 并生成统一的 hierarchy snapshot；同时通过 `render_alias_hierarchy_text` 输出包含 canonical path、group 和 alias 的 plaintext tree，方便 Android、CLI 以及调试工具直观查看 alias 中 canonical 的层级关系，避免 presentation 层自行解析 TOML 或从展示数据推导层级结构。该能力同时包括：`DescribeAliasHierarchy` 返回供 Android 和 CLI 展示的快照；`ValidateAliasHierarchyDocuments` 校验单个文档及跨文件 alias 唯一性；`CreateAliasHierarchyDocument` 创建带有 parent 和空 aliases 表的初始 TOML。

### 技术改进/重构 (Changed/Refactor)

本次改动的目标是将 alias TOML 的解析、校验、序列化和迁移计划统一收敛到 Core，避免 Android 与 Windows CLI 各自维护重复逻辑，并确保 TXT、TOML 与数据库修改通过统一的候选文件和原子迁移流程完成。

* 将 alias TOML 的 hierarchy、校验、canonical 路径计算、编辑和迁移语义统一收敛到 `tracer_core`。mapping、tree renderer 和 editor 共用同一个 `ActivityHierarchyDocument`，并提供带源文件、行列号的 TOML 校验诊断，避免 Android 与 Windows CLI 各自维护解析、序列化、遍历和规则推导而产生行为漂移。
* 将 C ABI runtime 入口从 `tracer_core_runtime_txt_json` 重命名为 `tracer_core_runtime_config_json`。入口现在同时承载 TXT 结构化编辑、canonical 活动名替换、alias hierarchy 编辑/校验/创建/渲染及 canonical 变更迁移计划；本次仅统一 runtime 命名，不改变既有 action 语义。由于当前 ABI 不要求旧版本兼容，旧符号同步移除，并更新动态加载、JNI 注册、能力字段、文档和测试。
* 在 `tracer_core_runtime_config_json` 增加 `apply_alias_hierarchy_operation`、`describe_alias_hierarchy`、`validate_alias_hierarchy_documents`、`create_alias_hierarchy_document` 和 `render_alias_hierarchy_text` action；删除旧的 `rename_alias_canonical` action 以及独立的 `tracer_core_render_alias_tree_text_json` export，树渲染统一走 runtime hierarchy action。
* 新增 `rewrite_alias_hierarchy_document` action，用于 raw TOML 编辑：Core 接收原始 TOML 和编辑后的 TOML，重新校验并返回 Core 序列化的 updated TOML、canonical replacements、alias-key replacements 和 hierarchy snapshot。这样可以避免宿主自行解析或序列化 TOML，保证所有 alias TOML 修改遵循 Core 的统一规则。Android/CLI 不得直接保存 alias TOML，所有 alias TOML 修改必须以 Core 返回结果进入 `RuntimeActivityHierarchyMigrationService` 或等价的宿主迁移流程；Core 不直接访问宿主文件系统或数据库。
* Android 新增 `AliasHierarchyGateway` 与 runtime service。structured editor、raw TOML editor 校验、导入 alias 校验、创建 alias 文件和 hierarchy 展示均改为消费 Core snapshot/operation 结果。这样可以删除 Android 与 Core 重复的 alias 业务逻辑，降低两端行为不一致的风险。Android 仅负责收集输入、遍历文件、调用 Core TXT replacement、候选数据库重建和原子迁移，不直接保存 alias TOML。删除 Android 本地 alias TOML parser、serializer、editor codec、hierarchy validator 和本地编辑 use case。
* Android 的 `group alias` 改名统一作为完整 alias token 迁移处理：Core 返回 `alias_replacements`，`RuntimeActivityHierarchyMigrationService` 先生成带新 TOML 和新 alias token 的候选文件集，再重建候选数据库并原子切换。这样可以避免 alias token 与 TOML 修改只提交一半，保证引用关系完整；即使 replacement 为空，alias TOML 变更也必须经过该事务流程。
* 跨 alias TOML 移动时，Core 必须统一校验并产出 source/destination TOML 的更新结果及完整 canonical/alias replacement 计划。宿主不得先提交其中一个 TOML，所有相关 TOML、TXT 和数据库必须在候选成功后一次性原子切换，防止迁移过程中出现文件和数据库状态不一致。
* Windows CLI 新增 `AliasHierarchyClient`。add、promote、add-group-alias、rename-group-alias、move-config 等命令改为调用 Core operation；move 和 rename-group 消费 Core 返回的 updated TOML 与 replacements，CLI 仅保留 TXT 替换、回滚和候选数据库重建。tree 命令改为请求 Core 渲染。这样可以让 CLI 与 Android 共用同一套 Core operation 语义，删除 Rust 本地 alias TOML 解析、序列化、遍历、校验、canonical 推导和旧 rename binding。
* 调整配置资产分层：当时将测试数据与分发数据拆成独立资产来源，所有旧 alias TOML 更新为 canonical-key-first、array-valued 格式，Android 和 Windows CLI 的运行时快照及构建/测试脚本同步切换到对应资产来源。后续目录协议进一步收敛为程序资源 `assets/tracer_core/program`、默认活动分类 `assets/tracer_core/defaults/activity_hierarchy` 和测试活动分类 `test/data/activity_hierarchy`，并通过统一配置分发命令生成平台快照。
* 同步更新 Core、transport、C ABI、JNI、Android、Windows CLI、配置 bundle 和 infrastructure 测试，覆盖 hierarchy 编辑、canonical replacement、树渲染、跨文件 alias 冲突、空白分发配置和 runtime 入口改名，确保统一 Core 边界、原子迁移流程和新 ABI 入口没有回归。

### 弃用/删除 (Deprecated/Removed)

* 删除旧的 alias TOML `alias = "canonical"` 解析契约；canonical 必须位于 TOML key，alias 必须位于非空字符串数组。
* 删除旧 `rename_alias_canonical` action、`tracer_core_runtime_txt_json` ABI 符号和独立 alias tree renderer export，以及 Android/CLI 内部重复的 alias hierarchy 语义实现。

### 兼容性说明

* 本版本的 alias TOML 迁移不仅支持 canonical 改名，也统一覆盖所有 hierarchy 内容修改。表现层不得从展示树反推 TOML 或迁移计划；它们只应读取文件、收集输入、调用 Core operation/raw-TOML validation-rewrite port，并把 Core 返回的 TOML 和 replacement 交给宿主迁移服务，由迁移服务负责 TOML/TXT/数据库落盘。
* `CreateAliasHierarchyDocument` 产生的初始 alias TOML 也必须经过宿主迁移服务提交；空 replacement 不代表可以调用普通 TOML 保存接口。
* 本轮收口范围仅覆盖 alias TOML；charts、meta、reports 等其他 TOML 类型仍需由各自的 Core owner/port 负责。
