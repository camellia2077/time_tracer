## [v0.10.3] - 2026-07-06

### 新增功能 (Added)
* 新增别名列表与规范名称映射的查询接口，支持 `DataQueryAction::kActivityHierarchyLeafMappings` 查询指令。此项改动是为了解决之前底层仅支持单向的 alias 转换为 canonical 映射（例如从 `数据结构` (alias) 转换为 `study_computer_data_structure` (canonical)）的局限，通过 `BuildActivityHierarchyLeafMappingsContent` 导出完整的反向映射 JSON 列表，以支持安卓端拉取别名数据实现从 `study_computer_data_structure` (canonical) 反查并回填 `数据结构` (alias) 的建议录入机制。
* 新增原始记录文件解析与校验对规范名（canonical）的直接输入与解析支持（更新 `LineRules` 初始化及 `ValidateActivityNameForRecord`）。此前系统仅支持输入较短的别名并将其转换为带层级路径的规范名以构建树状数据结构并入库（例如通过手动录入较短的 `高等数学` (alias) 转换为 `study_math_calculus` (canonical)，日常无直接录入规范名的使用场景）。本次改动是为了配合 suggestions 支持以规范名（canonical）格式输出并直接用于快捷录入的新场景，允许系统直接解析、校验并结构化提取以规范名形式写入的记录事件。
* 新增活动别名配置与数据备份包的导入、解包及安装核心服务（`tracer_exchange_service` 模块与 `pipeline_converter_config_install.cpp`）。提供对外部 `.toml` 别名配置文件及加密数据包的完整解密、解包、校验及 runtime 目录热安装策略，为表现层的高级配置导入与数据恢复提供底层 C++ JNI/C-API 能力支撑。

### 技术改进/重构 (Changed/Refactor)
* 优化 suggestions 查询逻辑，放宽对建议过滤参数的输入限制以响应安卓端 Picker 页面的即时响应与停用清空特性。此前在输入新参数时，若用户清除输入框中原有的数字（此时数值临时为 `0` 或空），会因参数校验限制而导致报错或无法录入。本次改动明确将 `lookbackDays` (lookback_days) 或 `limit` (limit) 传入 `0` 或负数定义为“跳过数据库查询”的合法业务语义（即用户表达不显示任何 suggestions 筛选结果的诉求），在底层直接截断并返回空列表以防止 SQLite 查询报错，保障上层界面的流畅编辑体验。
* 重构日期行（Day Marker）的匹配与校验规则，将以往的 4 位纯数字日期行（例如 `0301`）统一规范化为 5 位且以字母 `d` 开头的日期行格式（例如 `d0301`），并同步更新了 `LineRules::IsDate`、`IsDayMarkerLine`、`BuildDayMarkerLine` 的识别逻辑与全部相关单元测试数据。**此项改动旨在消除解析歧义并提升文本自读性**：因表示时间的 `HHMM` 行（例如 `0809` 表示 8点09分）与旧版表示日期的 `MMDD` 行（例如 `0301`）均由 4 位数字组成，给底层解析器带来了语法歧义；同时，新设计的 `dMMDD` 格式（如 `d0301`）保留了月份数值（`MM`），使得用户和解析器直接阅读某一行原始记录文件内容即可确定具体的月份与天数并结构化为 struct 实体，无需向上追溯寻找月份标题行 `mMM`。
