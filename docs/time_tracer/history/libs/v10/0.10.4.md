## [v0.10.4] - 2026-07-16

### 新增功能 (Added)
* 新增基于加权项目树的 composition 查询结果模型，将 root breakdown 的持续时间、占比和出现次数统一编码到树节点，使 Pie 和 Treemap 能够点击 root 后继续查看其子节点的比例分布。
* 扩展 runtime query 能力，将项目树查询收敛到统一的 `runtime_query` action，并支持多层级树查询的时间范围、最大深度等参数通过统一请求协议传递。
* 完善共享 `tracer_exchange` 的配置与文本处理事务，以支持 Android 的 TXT/TOML 非压缩导出与配置恢复，并同时满足 Windows CLI 的跨主机配置导入、校验和数据库重建流程；导入时原子应用配置、更新文本根目录、重建数据库，并保留导入包未覆盖的本地月份，避免恢复操作意外丢失本地数据。

### 技术改进/重构 (Changed/Refactor)
* 重构混合时间线的解析、转换和统计边界，使点事件与区间事件在转换后统一推进最后已知时间边界，并保持合法时间缺口不被隐式补全，避免把没有记录的时间误算为活动持续时间；重叠记录继续被拒绝。
* 重构活动映射与统计计算链路，统一 alias、canonical activity path、项目树节点以及 report composition 的字段语义，补充节点的父级时长占比和 occurrence count。
* 重构 converter 配置加载与校验流程，统一 `interval_processor_config.toml`、`alias_mapping.toml` 及分拆的 `converter/aliases/*.toml` 配置来源，并同步更新配置 bundle、运行时配置和 exchange 配置安装逻辑。
* 统一查询、报告和树数据的 DTO、JSON schema 与 transport codec，更新 C ABI、JNI 注册和 runtime capability contract，使 Android 与 Windows CLI 使用同一套 query/report 响应语义。
* 更新日期与时间边界处理、TXT 解析及结构校验逻辑，兼容当前 point/interval 混合输入，并同步调整数据查询映射、语义 JSON 输出和相关测试 fixtures。

### 弃用/删除 (Deprecated/Removed)
* 删除独立的 `tracer_core_runtime_tree_json` C ABI、JNI `nativeTree` 入口及对应 transport/runtime capability 声明。旧的独立 tree 响应模型无法满足 composition 图表逐层下钻的需求，现由统一的 `runtime_query` tree action 提供完整多层级节点、占比和时长信息。
* 删除独立的 `duration_rules.toml` 配置文件及其加载、校验和测试 fixture。此前该配置试图在 TXT 输入端按持续时间把 alias 自动转换为 `rest_short`、`rest_medium`、`rest_long` 等不同 token；本次移除这一输入端设计，保留原始数据并在解析后写入数据库，持续时间筛选和分类统一留到查询阶段处理。
* 删除依赖已废弃 `duration_rules.toml` 的旧 `tracer_exchange` 导出/导入端到端测试及其 fixture，保留 exchange package 编解码、SHA-256 完整性和 manifest 路径校验测试。
