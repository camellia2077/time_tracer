## [v0.10.8] - 2026-07-29

### 关联版本

* 本版本的 activity hierarchy 能力由 Windows CLI `v0.4.5`、Android `v0.6.2` 和 log_generator `v0.2.6` 消费。

### 新增功能 (Added)

本次改动的核心目的是让 activity hierarchy 成为可调整的活动分类边界。presentation 可以将 activity 迁移到其他 TOML 分类下，从而修正活动误分组，或主动改变活动的 `parent` 分组；配置变化会同步影响统计报告中的活动分组展示。同时，通过重命名 TOML 文件和 `parent`，可以修正或调整报告中的分类名称。

* 新增 Core activity hierarchy 迁移能力，支持将 activity 从一个 `activity_hierarchy` TOML 分类迁移到另一个分类，从而改变 activity 的 `parent` 分组、修正错误分类，并生成对应的 canonical activity name replacement 计划，供 presentation 消费。

### 技术改进/重构 (Changed/Refactor)

* 将存储 canonical alias activity names 的配置目录从 `aliases/` 重命名为 `activity_hierarchy/`。这些 TOML 文件主要描述 activity 的层级结构，alias 和 canonical 都只是层级中的 value；使用 `aliases` 容易造成“配置只用于 alias”的误解，也会让“移动到某个 aliases TOML”等交流表述产生歧义。相关目录变更同步更新配置加载、默认配置、bundle、分发资产、测试资产及各宿主运行时快照。
* 统一 Core 对 activity hierarchy TOML 的处理，支持迁移 activity、重命名 canonical、重命名 activity hierarchy TOML 文件以及重命名对应的 `parent`。文件和 `parent` 重命名用于调整统计报告中的分类名称，也用于修正此前写错的名称；相关变更统一产出 TOML 更新结果和 canonical replacement，供 presentation 层执行原子迁移。
* 将 activity hierarchy 的层级解析、canonical 路径计算、文本渲染和迁移语义收敛到 Core，新增对应的 hierarchy tree、文本渲染器和迁移测试，避免 CLI 与 Android 分别推导配置语义。
* 同步更新 C ABI、配置同步工具、exchange/runtime 配置消费及跨平台测试，使 `activity_hierarchy/` 成为 canonical activity 配置的唯一目录口径。

### 弃用/删除 (Deprecated/Removed)

* 删除旧的 `aliases/` 配置目录及其运行时快照路径；canonical alias activity names 必须从 `activity_hierarchy/` 下的 TOML 文件加载。

### 兼容性说明

* 本版本改变了配置目录和 hierarchy TOML 文件命名口径，宿主必须同步刷新配置 bundle，并使用 Core 返回的 TOML 更新结果和 replacement 计划完成迁移；不能继续依赖旧的 `aliases/` 路径或在 presentation 层自行推导 canonical。
