# libs 重构收尾指南

## 适用范围

用于 `libs/**` 的内部重构收尾，不替代各目录下的 `AGENTS.md`。

## 本次重构应检查

### 1. 模块实现是否重复或漂移

如果同一能力同时存在：

- `.cpp`
- `.module.cpp`
- 共享头文件或 `.inc`

应确认两条构建路径不会各自维护同一套业务逻辑。可以抽取共享的、职责明确的内部 helper。

### 2. 公共内部接口语义是否保持

重构实现时，要确认类似 `LoadMergedToml()` 这类已有接口的职责没有被悄悄后移或改变。

即使接口不是对外公开 API，也要保持其现有语义，除非本次明确要求改变。

### 3. 派生配置是否只有一个事实来源

如果某项配置可以从另一项配置推导：

- 明确哪个是源配置
- 派生值由 loader 统一生成
- 不要让不同模块分别重新推导
- 删除已经失效的旧配置读取逻辑

### 4. 语义边界是否仍然清楚

配置映射、活动名转换、parser、validator、mapper 各自只处理自己的职责。

例如：

- alias mapping 只负责名称映射
- wake 语义由 parser / core 语义逻辑判断
- interval wake 不能因为名称匹配就被当成点事件 wake

### 5. 最小验证

至少运行本次能力对应的验证 profile，并确认：

- modules 构建路径通过
- 非 modules 构建路径通过
- 相关回归测试通过
